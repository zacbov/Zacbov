Mémo débutant — Terminal, Linux, Docker, localhost et serveur Python

Une page pour repartir de zéro : comprendre ce que tu tapes, où tu es, pourquoi certaines erreurs arrivent, et quelles commandes de base connaître quand on vient de Windows/Mac.

Idée générale Terminal Chemins Commandes utiles SSH localhost Serveur Python Docker 3 services Erreurs fréquentes Recettes Logs & arrêt

1. L’idée générale : tu navigues entre plusieurs machines

Quand tu tapes des commandes, la question la plus importante est toujours : où suis-je ?

Ton PC ou Mac

C’est ta machine de travail. Sur Windows, tu utilises PowerShell. Sur Mac, tu utilises Terminal.

PS C:\Users\Toi>

Le serveur distant

Quand tu te connectes en SSH, tu contrôles une autre machine, par exemple un NAS ou un serveur Linux.

tice-nas@TICE:/volume1/docker$

Le conteneur Docker

Un conteneur est comme une mini-machine isolée dans le serveur. Tu peux entrer dedans.

root@31a9ffb529fe:/app#
Règle d’or :
Une commande peut marcher dans un endroit et échouer dans un autre. Beaucoup d’erreurs viennent du fait qu’on tape une commande prévue pour Docker directement sur le serveur, ou une commande prévue pour Linux dans PowerShell.

2. Terminal, shell, prompt : le vocabulaire

MotDéfinition simple
TerminalLa fenêtre où tu tapes les commandes.
ShellLe programme qui interprète tes commandes : PowerShell, bash, sh, zsh...
PromptLa ligne qui indique où tu es et attend ta commande.
CommandeUn ordre donné à l’ordinateur : ls, cd, docker ps...
ArgumentUne information donnée à une commande. Exemple : dans cd /volume1/docker, le chemin est l’argument.
OptionUn réglage de commande, souvent avec - ou --. Exemple : ls -lah.

Lire le prompt

tice-nas@TICE:/volume1/docker$
  • tice-nas : l’utilisateur connecté.
  • TICE : le nom de la machine.
  • /volume1/docker : le dossier actuel.
  • $ : utilisateur normal.
root@31a9ffb529fe:/app#
  • root : super-utilisateur dans le conteneur.
  • 31a9ffb529fe : identifiant du conteneur.
  • /app : dossier actuel.
  • # : droits élevés.
Si une commande affiche une ligne qui commence par >, cela veut souvent dire que le shell attend la suite d’une commande commencée mais pas terminée. Ça arrive quand tu as copié une commande multi-lignes de travers.

3. Comprendre les chemins de fichiers

Windows vs Linux

WindowsLinux / Mac
C:\Users\Nom\Documents/home/nom/Documents
Utilise souvent \Utilise toujours /
Les majuscules/minuscules sont souvent moins strictesLinux distingue Sarcoptes et sarcoptes

Chemin absolu vs relatif

Un chemin absolu part de la racine :

/volume1/docker/app/server.py

Un chemin relatif part du dossier où tu es :

app/server.py

Commandes de navigation

pwd          # affiche le dossier actuel
ls           # liste les fichiers
ls -lah      # liste détaillée, avec fichiers cachés et tailles lisibles
cd dossier   # entre dans un dossier
cd ..        # remonte d’un dossier
cd /         # va à la racine

Espaces et accents dans les chemins

Si un nom contient des espaces, mets des guillemets :

cd "/volume1/docker/mon dossier"

Ou échappe l’espace avec \ :

cd /volume1/docker/mon\ dossier

Redirection et pipe

Le pipe | envoie le résultat d’une commande dans une autre.

La redirection > écrit dans un fichier et remplace son contenu :

echo "bonjour" > test.txt

La redirection >> ajoute à la fin :

echo "suite" >> test.txt

5. SSH : contrôler un serveur à distance

SSH permet de contrôler une machine distante depuis ton PC.

ssh utilisateur@adresse_ip

Exemple :

ssh tice-nas@192.168.0.93

Première connexion

SSH demande souvent :

Are you sure you want to continue connecting?

Il faut écrire :

yes

Quitter SSH

exit
Tu peux avoir un message du type Could not chdir to home directory. Ce n’est pas forcément grave : ça veut dire que le dossier personnel de l’utilisateur n’existe pas, mais tu es quand même connecté.

6. Comprendre localhost

localhost veut dire : cette machine-ci.

Où tu tapes l’adresse ?Ce que signifie localhost
Dans ton navigateur sur ton PCTon PC
Dans le NASLe NAS
Dans un conteneur DockerLe conteneur lui-même
Une erreur classique : une page web utilise http://localhost:8080. Sur ton PC, cela cherche un serveur sur ton PC, pas sur le NAS. Pour accéder au NAS, il faut utiliser son IP, par exemple http://192.168.0.93:8080.

Ports

Un port est comme une porte d’entrée d’un service.

  • 80 : HTTP classique
  • 443 : HTTPS
  • 8080 : souvent utilisé pour les applications web de test
  • 22 : SSH

Dans Docker :

-p 8080:8080

signifie : le port 8080 du NAS redirige vers le port 8080 du conteneur.

7. Comment fonctionne un serveur Python

Un serveur Python est un programme qui reste lancé et répond à des requêtes HTTP.

Exemple minimal avec Flask

from flask import Flask

app = Flask(__name__)

@app.route("/")
def accueil():
    return "Bonjour"

app.run(host="0.0.0.0", port=8080)

Ce que ça veut dire

LigneExplication
Flask(__name__)Crée l’application web
@app.route("/")Déclare une adresse web
return "Bonjour"Réponse envoyée au navigateur
host="0.0.0.0"Écoute toutes les interfaces réseau
port=8080Utilise la porte 8080

Pourquoi 0.0.0.0 ?

127.0.0.1 ou localhost limite souvent l’accès à la machine elle-même. 0.0.0.0 permet d’accéder au serveur depuis d’autres machines du réseau, si le pare-feu et le réseau l’autorisent.

HTTP 200, 304, 404

CodeSignification
200OK, la requête a réussi
304Le navigateur utilise une version en cache
404Non trouvé ou ressource non ouvrable selon le code du serveur
500Erreur interne du serveur

8. Docker expliqué simplement

Docker permet de lancer une application dans un environnement isolé, reproductible, avec ses dépendances.

Image

Modèle figé, comme une recette ou une photo du système.

histoviewer

Conteneur

Instance lancée d’une image, comme une application en cours d’exécution.

histoviewer

Volume

Dossier du serveur branché dans le conteneur.

-v /nas/dossier:/conteneur/dossier

Dockerfile

Le Dockerfile décrit comment fabriquer l’image.

FROM python:3.11-slim

RUN apt-get update && apt-get install -y openslide-tools

WORKDIR /app

RUN pip install flask pillow openslide-python

COPY app/server.py /app/server.py

EXPOSE 8080

CMD ["python", "/app/server.py"]

Build vs run

CommandeRôle
docker buildFabrique une image depuis le Dockerfile
docker runLance un conteneur depuis une image
docker restartRedémarre un conteneur existant
docker logsAffiche ce que l’application écrit

Commande type

sudo docker run -d \
  --name monserveur \
  --restart unless-stopped \
  -p 8080:8080 \
  -v /volume1/docker/data:/data:ro \
  monimage
  • -d : en arrière-plan
  • --name : nom du conteneur
  • --restart unless-stopped : redémarre automatiquement
  • -p : expose un port
  • -v : branche un dossier

.dockerignore

Docker envoie le dossier courant comme contexte de build. Si ce dossier contient des dizaines de Go, le build devient énorme. Le fichier .dockerignore permet d’exclure des dossiers.

slides/
convertion/
@eaDir/
\#recycle/
*.svs
*.ndpi
*.mrxs
*.tif
*.tiff
Piège rencontré : #recycle/ commence par #, donc peut être compris comme un commentaire. Il faut écrire \#recycle/.

13. À quoi servent PowerShell, Docker et le serveur Python ?

Ces trois éléments ne font pas la même chose. Une grande partie de la confusion vient du fait qu’on les utilise parfois dans la même session, mais ils n’ont pas le même rôle.

PowerShell

Rôle : ton terminal côté Windows.

Il sert à envoyer des commandes depuis ton PC : te connecter en SSH, copier des fichiers, lancer des commandes locales, ou piloter un serveur distant.

ssh tice-nas@192.168.0.93

Docker

Rôle : lancer une application dans un environnement isolé.

Docker contient Python, les bibliothèques nécessaires, le serveur, et les outils installés dans l’image.

sudo docker restart histoviewer

Serveur Python

Rôle : l’application web qui répond au navigateur.

Il écoute sur un port, reçoit les requêtes HTTP, lit des fichiers, et renvoie du HTML, du JSON ou des données.

python server.py /slides 8080

Image mentale simple

Ton PC Windows
  └── PowerShell
        └── SSH vers le NAS
              └── Docker sur le NAS
                    └── Conteneur histoviewer
                          └── Serveur Python Flask

Tu peux voir ça comme des poupées russes : PowerShell peut te connecter au NAS, le NAS lance Docker, Docker lance le serveur Python.

Qui fait quoi ?

BesoinOutil concernéExemple
Me connecter au NAS depuis Windows PowerShell + SSH ssh tice-nas@192.168.0.93
Voir où je suis dans les dossiers du NAS Shell Linux du NAS pwd, ls -lah
Lancer, arrêter ou redémarrer l’application Docker sudo docker restart histoviewer
Voir les logs de l’application Docker sudo docker logs histoviewer
Entrer dans l’environnement isolé de l’application Docker sudo docker exec -it histoviewer bash
Modifier le comportement du site ou de l’API Serveur Python Modifier server.py
Modifier l’interface affichée dans le navigateur HTML/JS côté viewer Modifier viewer.html
Rendre le site accessible depuis un navigateur Serveur Python + réseau + port http://192.168.0.93:8080

PowerShell : quand l’utiliser ?

PowerShell est ton point de départ quand tu es sur Windows.

Tu l’utilises pour :

  • te connecter au NAS avec SSH ;
  • tester une connexion réseau ;
  • copier des fichiers avec scp si besoin ;
  • lancer des commandes Windows locales.
# Se connecter au NAS
ssh tice-nas@192.168.0.93

# Tester si le NAS répond
ping 192.168.0.93

# Tester une URL depuis Windows
curl http://192.168.0.93:8080
À ne pas oublier :
Quand tu es dans PowerShell, les chemins Linux comme /volume1/docker n’existent pas localement. Ils existent sur le NAS après connexion SSH.

Docker : quand l’utiliser ?

Docker sert à gérer le conteneur, c’est-à-dire l’environnement dans lequel tourne ton application.

Tu l’utilises pour :

  • démarrer ou arrêter l’application ;
  • voir les logs ;
  • entrer dans le conteneur ;
  • monter des dossiers du NAS dans le conteneur ;
  • reconstruire l’image si tu modifies les dépendances ou le code copié dedans.
# Voir les conteneurs actifs
sudo docker ps

# Voir tous les conteneurs
sudo docker ps -a

# Redémarrer
sudo docker restart histoviewer

# Voir les logs
sudo docker logs histoviewer

# Entrer dans le conteneur
sudo docker exec -it histoviewer bash

Serveur Python : quand intervient-il ?

Le serveur Python est le programme qui tourne à l’intérieur du conteneur. Il reçoit les requêtes du navigateur.

Exemples de requêtes :

GET /
GET /api/slides
GET /api/info/nom_du_fichier
GET /api/dzi/nom_du_fichier.dzi

Dans ton code, Flask associe ces adresses à des fonctions Python :

@app.route("/api/slides")
def list_slides():
    return jsonify(...)

Donc quand tu tapes dans le navigateur :

http://192.168.0.93:8080/api/slides

Le navigateur contacte le serveur Python, qui exécute la fonction associée et renvoie une réponse.

Différence entre arrêter Docker et arrêter Python

SituationCe qui se passe
Ctrl + C après python server.py Tu arrêtes le serveur Python lancé directement au premier plan.
sudo docker stop histoviewer Tu arrêtes tout le conteneur, donc aussi le serveur Python dedans.
sudo docker restart histoviewer Docker arrête puis relance le conteneur et le serveur Python.
sudo docker logs -f histoviewer puis Ctrl + C Tu arrêtes seulement le suivi des logs ; le serveur continue de tourner.

Quand faut-il rebuild ?

ActionRebuild ?Pourquoi
Ajouter des fichiers dans un dossier monté avec -v Non Docker lit directement le dossier du NAS.
Supprimer ou déplacer des fichiers dans un dossier monté Non Un simple restart suffit parfois à rafraîchir l’état.
Modifier server.py s’il est copié dans l’image par le Dockerfile Oui L’image contient l’ancienne version tant qu’elle n’est pas reconstruite.
Modifier viewer.html s’il est copié dans l’image Oui Le conteneur sert le fichier copié au build.
Modifier le Dockerfile Oui Il faut reconstruire l’environnement.
Changer la commande docker run ou les volumes Pas forcément rebuild, mais recréer le conteneur Les volumes et ports sont définis au lancement du conteneur.

Résumé ultra court

ServiceQuestion à se poserCommande typique
PowerShell Comment accéder au serveur depuis mon PC ? ssh utilisateur@ip
Docker Comment gérer l’environnement où tourne l’application ? sudo docker restart histoviewer
Serveur Python Que fait mon application quand le navigateur l’appelle ? python server.py
Réflexe pratique :
Si le problème est “je n’arrive pas à me connecter”, pense réseau/PowerShell/SSH.
Si le problème est “le conteneur ne tourne pas”, pense Docker.
Si le problème est “l’URL répond mal ou renvoie une erreur”, pense serveur Python et logs.

14. Quand un serveur affiche les logs et bloque le terminal

Quand tu lances un serveur directement dans le terminal, par exemple :

python server.py
# ou
flask run
# ou
npm run dev

le programme reste actif. Il écoute les requêtes et affiche les logs en direct. C’est normal que tu ne récupères pas tout de suite une nouvelle ligne de commande.

Exemple

Serveur démarré sur http://localhost:8080
127.0.0.1 - - "GET / HTTP/1.1" 200 -
127.0.0.1 - - "GET /api/slides HTTP/1.1" 200 -

Tant que le serveur tourne, le terminal est occupé par ce processus.

À retenir :
Voir les logs ne veut pas dire que le terminal bug. Cela veut dire que le serveur tourne au premier plan.

Arrêter proprement un serveur lancé au premier plan

La commande la plus importante :

Ctrl + C

Sur Windows, Mac et Linux, Ctrl + C envoie un signal d’arrêt au programme actif. Dans la majorité des cas, cela arrête le serveur et te rend la main.

Après arrêt, tu dois revoir un prompt du type :

tice-nas@TICE:/volume1/docker$
# ou
PS C:\Users\Toi>
# ou
root@xxxx:/app#

Ne pas confondre Ctrl+C et fermer la fenêtre

ActionEffet
Ctrl + CArrête le processus actif dans le terminal.
Fermer la fenêtreCoupe la session, parfois brutalement.
exitQuitte le shell actuel, mais n’arrête pas toujours un serveur si un processus tourne encore.

Lancer un serveur en arrière-plan

Si tu veux récupérer le terminal tout de suite, tu peux lancer une commande en arrière-plan avec & :

python server.py &

Mais pour débuter, ce n’est pas toujours le plus simple, car il faut ensuite savoir retrouver et arrêter le processus.

Voir les processus en cours

ps aux | grep python

Cette commande cherche les processus Python actifs.

Arrêter un processus avec son PID

Si tu vois une ligne comme :

tice-nas  12345  ...  python server.py

Le nombre 12345 est le PID, c’est-à-dire l’identifiant du processus. Tu peux l’arrêter avec :

kill 12345

Si le processus refuse de s’arrêter :

kill -9 12345
Attention :
kill -9 force l’arrêt. À utiliser seulement si Ctrl + C ou kill simple ne fonctionne pas.

Cas Docker : voir les logs sans bloquer définitivement

Avec Docker, tu peux afficher les logs :

sudo docker logs histoviewer

Cette commande affiche les logs déjà présents puis te rend la main.

Si tu utilises :

sudo docker logs -f histoviewer

le -f signifie follow : tu suis les logs en direct. Le terminal reste donc occupé.

Pour arrêter de suivre les logs sans arrêter le conteneur :

Ctrl + C
Important :
Ctrl + C sur docker logs -f arrête seulement l’affichage des logs. Le conteneur continue de tourner.

Cas Docker : arrêter vraiment le serveur

Si ton serveur tourne dans Docker, il vaut mieux arrêter le conteneur :

sudo docker stop histoviewer

Le redémarrer :

sudo docker start histoviewer

Ou faire les deux d’un coup :

sudo docker restart histoviewer

Quand tu vois un > au début de la ligne

Exemple :

>   -v /volume1/docker/slides:/slides \
>   histoviewer \
>   bash

Ce n’est pas une erreur en soi : cela veut dire que le shell attend la suite d’une commande multi-lignes. Mais si tu as collé une commande de travers, tu peux te retrouver bloqué.

Pour annuler et repartir proprement :

Ctrl + C

Réflexe simple

  1. Je vois des logs défiler : le serveur tourne probablement.
  2. Je veux arrêter ce serveur lancé directement : Ctrl + C.
  3. Je suis en train de suivre des logs Docker : Ctrl + C arrête seulement l’affichage.
  4. Je veux arrêter le serveur Docker : sudo docker stop histoviewer.
  5. Je vois un > et je ne comprends plus : Ctrl + C.

15. Ce que tu dois retenir en priorité

  1. Avant de taper une commande, regarde ton prompt : PC, NAS ou Docker ?
  2. localhost veut toujours dire “la machine où je suis”.
  3. Un conteneur Docker est isolé : ses chemins ne sont pas forcément ceux du NAS.
  4. -v dossier_nas:dossier_docker est le pont entre les deux.
  5. Un serveur Python écoute sur un port, par exemple 8080.
  6. docker build fabrique l’image ; docker run lance le conteneur.
  7. Pour ajouter des données, on ne rebuild pas : on redémarre juste si nécessaire.
  8. Les logs sont tes meilleurs amis : sudo docker logs nom_du_conteneur.
Réflexe anti-panique :
1. pwd — où suis-je ?
2. ls -lah — qu’est-ce qu’il y a ici ?
3. sudo docker ps — le conteneur tourne-t-il ?
4. sudo docker logs histoviewer — que dit l’application ?
