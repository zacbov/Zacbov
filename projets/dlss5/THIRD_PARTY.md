# Source and binary provenance

- [Merserk/dlss5-visual-enhancer](https://github.com/Merserk/dlss5-visual-enhancer): reference for the standalone image workflow and user-facing neural controls. Python application code is not embedded in this effect.
- [rakanki911/DLSS5-Swapper](https://github.com/rakanki911/DLSS5-Swapper): reference for the installed RenoDX/Feeder controls. The effect does not inject ReShade or modify a game installation.
- [DaniilSokolyuk/video2dlssnr](https://github.com/DaniilSokolyuk/video2dlssnr): MIT-licensed D3D12 texture/compute utilities and GPU Lucas–Kanade optical flow are included in `third_party/video2dlssnr`. Its license is retained there. Local modifications select an NVIDIA GPU, bound fence waits, and prevent destructor exceptions. Its native feature-18 implementation also informed the runtime parameter contract. Its diagnostic binary-patching code is not used.
- [NVIDIA/DLSS](https://github.com/NVIDIA/DLSS): NGX headers in `third_party/ngx/include`; NVIDIA license retained in `third_party/ngx/LICENSE.txt`. The local `nvsdk_ngx_d.lib` was copied from `D:\CodexTemp\ReshadeCompositor\feeder\deps\DLSS\lib\Windows_x86_64\x64`.
- Adobe After Effects SDK: four user-supplied SDKs are used externally at build time. The Adobe SDK packages are not included in the source archive.
- [ChillFish8/av-denoise](https://github.com/ChillFish8/av-denoise), commit `583e028feec3ade28730318926528f7a8530bc9a`, Apache-2.0: the unchanged `av-denoise-core` source and license are vendored in `third_party/av-denoise`. The vendor workspace lists only the core member; the CLI and VapourSynth adapter are excluded. `denoiser/src/lib.rs` is this project's C ABI, RGB/YUV conversion, worker, and lifecycle integration. It calls the actual upstream NLMeans-HQ algorithm through Vulkan. CubeCL and other Rust dependencies are locked in `denoiser/Cargo.lock`; their published notices and package license declarations are collected in `third_party/av-denoise/dependency-licenses`. The bridge follows the upstream Windows module-retention approach so persistent GPU threads remain valid after host unload.

The two NVIDIA runtime DLLs were copied, without modification, from the user's `D:\Games\Red Dead Redemption 2` directory for this local installation. Their hashes and file versions are recorded in `dist/runtime-manifest.json`. The game files and installed ReShade configuration were not changed.

The common engine is named `nvngx.dll_dlss5ae.dll` because the installed community feature-18 runtime checks the calling module's filename when its exported entry points are called directly. The engine first initializes NGX through the SDK and attempts feature creation through the driver core, then uses the runtime exports when the core cannot create feature 18. No executable code, signatures, registry checks, or DLL contents are patched.

NVIDIA binaries and SDK components retain NVIDIA's terms; the upstream MIT license does not relicense them. The runtime files assembled here are for the user's local build. Public redistribution is a separate packaging decision.
